Session observability demo

A synthetic agent workload replayed through the Dynamo mocker. The router's session index tracks each session; a stats tracker turns that into the working set, thrash and per-session figures below.

Working set against capacity

Demand is the distinct tokens the active sessions will present next. Resident is what each tier holds. A shared prefix is counted once in both.

Thrash: prefix tokens a returning session had to rebuild

Tokens per 30 seconds. Recomputed means the prefix was in no tier. Reloaded means it was only in host memory.

Sessions

Active sessions, and how many have their GPU-resident prefix on more than one worker.

KV held for idle or finished sessions

Distinct GPU tokens that only inactive sessions still reference. This is evictable, so it matters only when it crowds out active demand.

Share of traffic the session metrics cover

Cumulative share of routed requests, and of input tokens, that carried a session ID. Everything else on this page describes only that share. Requests without an ID are routed as usual but are not tracked.

Prefix copies held by more than one worker

Tokens of session prefix that sit on a second (or third) worker: capacity spent on duplicates. It rises when the router spreads sessions that share a prefix, such as a parent and its subagents.

Cache reuse funnel

Cumulative input tokens narrowing from the prompt to what the worker reports reusing. F0 is every prompt token. F2 is the prefix the router estimates is cached on the best eligible worker. F3 is the same on the worker it chose. F4 is what the worker reports reusing. Each step counts tokens, not requests.

Where a returning session finds its prefix, by time since its last turn

Share of returning turns whose prior prefix was on the GPU, in host memory, or mostly missing (so recomputed), to within a tenth. Long gaps lose the GPU.

Distribution across all sessions in this run, including subagents. Context is the largest prefix a session presented.
